THIS APP IS BASICALLY A WORKFLOW ACCELERATOR FOR THE IMPORTING OF PURHASE ORDERS INTO THE ODOO DATABASE. THE IDEA BEHIND THIS APP IS THE USER WILL DROP THE PO EXCEL FILE IN THE FOLDER AS PER THE THE USER'S CHOICE AND THE APP WILL READ THAT FOLDER FOR ANY EXCEL FILE. THE USER WILL THEN SELECT THE PO FILE TO IMPORT AND THE APP WILL FIRST PARSE THE EXCEL FILE AND VALIDATE THE DATA IN THE EXCEL FILE. IF THE DATA IS VALID, THE APP WILL THEN IMPORT THE DATA INTO THE ODOO DATABASE. IF THE DATA IS INVALID, THE APP WILL THEN SHOW THE ERROR MESSAGE TO THE USER AND THE USER CAN THEN CORRECT THE DATA AND TRY AGAIN. THERE IS DUPLICATION CHECK IN THE APP FOR ANY FILE THAT HAS BEEN ALREADY IMPORTED. IT DOES THIS BY HASHING THE DATA AFT6ER PARSING AND STORING IT IN A LOCAL JSON FILE. THIS HASHING METHOD SAVES SPACE TOO. THERE IS ALSO THE FEATURE TO CONFIGURE THE FOLDER WHERE THE USER CAN DROP THE PO EXCEL FILE. BY DEAFAULT, IF NOT THERE THE APP WILL CREATE SOME FOLDERS FOR INCOMING ORDERS, PROCESSED ORDERS AND LOG FILES. AFTER A SUCCESSFUL IMPORT THE FILE IS MOVED TO THE PROCESSED FOLDER AND A LOG FILE IS CREATED IN THE LOG FOLDER. IF THE FILE IS NOT IMPORTED, THE FILE REMAINS IN THE SAME FOLDER AND THE ERROR WHICH CAUSED THE FAILURE IS DISPLAYED TO THE USER. THE IMPORT PROCESS IS ATOMIC IT EITHER FULLY IMPORTS THE FILE OR DOESN'T IMPORT AT ALL. NO PARTIAL IMPORT IS ALLOWED. IN THE FUTURE THERE WILL BE A FEATURE TO COMBAT ANY AMBIGUITY IN THE DATA. FOR EXAMPLE IF THE USER ENTERS A PRODUCT NAME WHICH IS NOT IN THE DATABASE, THE APP WILL SHOW THE USER A LIST OF SIMILAR PRODUCT NAMES AND THE USER CAN SELECT THE CORRECT PRODUCT NAME. ALSO UPON FAILURE OF IMPORTING THERE WILL BE AN OPTION TO TO OPEN THE EXCEL FILE FROM THE APP ITSELF. THE CURRENT GOAL OF THIS SPRINT IS TO IMPROVE THE UX AND MAKE IT INTUITIVE AND USER FRIENDLY.
